Changes

ConsoleWork lives in model.rs; ConsoleState.work is required on the wire and nullable. Busy owns a nonoptional Run/Count/Transaction/Edit/Probe, all five take_session callers classify their operation, and snapshots derive work directly from SessionSlot. Transaction, edit and probe acquisition now publish their Busy snapshot too. Count completion/drop/retirement uses the existing return/drop ownership paths. No driver/session signature or IPC command changed, and no persisted field was added.

TopBar shows Counting and Cancel/Esc during Count, keeps the finished run/results, preserves SQL Server session-reset/unknown-outcome guidance, and disables competing busy controls. Cancellation expands only to Count; ordinary Run behavior remains. Transaction/Edit/Probe have no Cancel action. Results controls respect Busy and Last is disabled during owned work.

The existing per-tab page queue carries request identity and the outstanding SQL Server count request. This serializes page requests even before the first Count snapshot without using that marker as UI activity. A newer page/filter/size intent invalidates an old Last reply before saved page changes. Only accepted runs persist a page. Cancel clears the queue before IPC, and session loss/disconnect/close discard queued intent. A count reply that precedes its clearing snapshot waits rather than sending a Busy page run. PostgreSQL retains metadata counts and can load a newer page while its count is pending.

Generated bindings and all typed fixtures were updated. README and count/paging architecture sentences describe the behavior. No routine, catalog, sidebar or driver files changed. The implementation follows the accepted sketch without a nonlocal design deviation.
