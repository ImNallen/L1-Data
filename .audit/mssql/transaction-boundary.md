# SQL Server transaction boundary design, R4

Recommend disabling SQL Server app-managed Manual mode and staged edits. Keep SQL Server connections, per-connection T-SQL, native Auto-commit scripts including explicit transactions, transaction buttons, catalogs, query results, table browsing, filters, sorting, and export. PostgreSQL keeps Manual mode and staged edits. This matches the requested SQL Server connection/dialect scope without promising PostgreSQL capability parity.

**The premise was written before testing.** `/tmp/l1data-mssql-trigger-boundary-r4-premise.md` states the proposed invariant that BEGIN plus final depth/XACT_STATE keeps accepted ordinary work rollbackable and staged submissions atomic. The counterexamples below falsify it. Transaction identity can detect replacement after execution; it cannot prevent or undo the earlier commit.

**Alternatives.**

| Option | Assessment |
| --- | --- |
| Reject opaque invoked code under a stable guard | Plausible only for a much narrower, proven command subset. Direct-target inspection misses cascades. Module definitions invoke database/server DDL handlers. Restricted metadata can omit all three. An unlocked check races. An enforceable version needs authoritative visibility, exact target/dependency resolution, permission handling, and stable locks over every reachable target, including indirect code paths. These probes establish necessary conditions, not a complete guard. Reject for this release. |
| Disable app-managed Manual and staged edits for SQL Server | Small, enforceable policy at Engine boundaries, independent of SQL grammar, hidden trigger definitions, session options, and concurrent schema changes. Retains the requested core feature. Recommended. |
| Server mechanism forbidding transaction ending | Tested XACT_ABORT, SERIALIZABLE, savepoints, and a table X lock do not provide it. No documented, tested mechanism compatible with the current Tiberius session model was established. Externally controlled distributed transactions or a different transaction protocol remain unproven; do not add services or driver complexity on that speculation. |
| Post-execution ID/depth checking | Useful only for outcome diagnostics. The changed data was already committed when the check runs. Reject as a rollbackability or atomicity fix. |

Microsoft documents that trigger statements after ROLLBACK can make changes that remain, and COMMIT requires only public membership. These are native semantics, not a missing client error check. [ROLLBACK TRANSACTION](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/rollback-transaction-transact-sql?view=sql-server-2017), [COMMIT TRANSACTION](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/commit-transaction-transact-sql?view=sql-server-ver15). Trigger metadata is visibility-filtered, and cascading actions invoke child triggers. [sys.triggers](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-triggers-transact-sql?view=sql-server-ver17), [sys.server_triggers](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-server-triggers-transact-sql?view=sql-server-ver17), [Cascading referential actions](https://learn.microsoft.com/en-us/sql/relational-databases/tables/primary-and-foreign-key-constraints?view=sql-server-ver15).

**Smallest proposed shapes and gates.**

1. Keep `DatabaseKind` as the authority. No new persisted capability flags, trigger allowlist, parser, or generalized capability service is needed. Add `ConfigureError::Unsupported { what: String }` and `ApplyError::Unsupported { what: String }`, consistent with existing `RunError::Unsupported`. Regenerate bindings. Keep Tauri and bridge forwarding signatures unchanged.
2. `Engine::console_configure` rejects SqlServer + Manual from the saved immutable connection kind before inserting or changing console state, including offline configurations. `txn::plan` refuses that pair defensively before any selected batch can run. Both Script and TablePage must be covered. Auto always plans Native. PostgreSQL keeps the existing wrapper rules.
3. `Engine::table_apply` rejects SQL Server before catalog reads, planning, opening a session, BEGIN, locks, or mutations, including empty submissions and calls inside native explicit transactions. Gate the actual configuration/session used, not a stale snapshot across an await. Keep an explicit unsupported SQL Server edit dispatch so an internal caller cannot accidentally send PostgreSQL edit SQL through that driver. The refusal must preserve any existing native transaction and its earlier work.
4. In `src/shell/TopBar.tsx`, make Manual unavailable for SQL Server with an explanation that native transaction statements remain available. Keep Commit/Rollback for every observed non-Idle transaction. `hasUncommittedWork` already does this irrespective of mode; do not regress it. Preserve depth, Busy, connection-loss, and cancellation behavior.
5. Make `gridEditing` return null for SQL Server using its catalog kind, so EditBar, insert/delete controls, keyboard editing, and context editing are unavailable while browse/filter/sort/copy remain. A short explanation should say SQL Server grid editing is unsupported and offer normal SQL execution. The Engine refusal remains authoritative. Coordinate this small predicate with the named-key worker because it shares ResultGrid.
6. Preserve loadability of saved Manual tabs. Do not silently change a restored SQL Server Manual tab to Auto and then run text under different commit semantics. Show the unsupported state and let the user explicitly choose Auto. Likewise refuse a target switch that would carry Manual onto SQL Server, or require an explicit mode choice. New SQL Server tabs already default to Auto. `tabFromSnapshot`, `reconfigure`, `setTabMode`, and `ensureConsole` are the relevant frontend paths.
7. Root's typed OutcomeUnknown must distinguish unconfirmed persistence from a known refusal or rollback. Remove the unconditional "Nothing was saved" prefix for uncertain outcomes and correct the blanket ApplyError doc comment. Preserve pending edits for inspection without implying retry is safe. No transaction-identity implementation is required to ship the bounded feature.

**Limits and ownership.** This proves rejection/deletion is the appropriate support contract; it does not prove the not-yet-implemented gates. No complete trigger-free subset or server prohibition mechanism was established. The scoped native probes are not a browser pass or a PostgreSQL compatibility run. Native Auto scripts can themselves commit, roll back, replace transactions, or leave an uncertain outcome, so the app must not advertise whole-script atomicity there. The final implementation belongs to root and the fresh backend worker. This agent stops with this report.

Attack the Premise replaced a post-execution check with a capability boundary. Boundary Discipline places enforcement in Engine entry points and driver dispatch. Model the Domain keeps the existing database kind and typed unsupported/outcome variants instead of inferred SQL safety. Prove It Works required actual persisted observer reads and verified cleanup.
