What changed

Engine::exact_row_count now requires (tab_id, db, schema, table, query). The expected DatabaseRef remains an exact canonical-target guard. All Rust callers, the Tauri one-line wrapper, dev-bridge dispatch, generated TypeScript command, frontend Last action, smoke arguments, and tests use the new signature. No legacy overload or new wire type was added.

PostgreSQL still counts on its metadata session. SQL Server uses the named live console's session through take_session and edit/return_session. It validates the live console identity, connected instance identity, canonical expected database, immutable SQL Server kind, native AutoCommit mode, and Busy slot around catalog/login awaits. It prefers the initialized session and opens a native session lazily only when needed. No console lock crosses network IO.

A count task owns the existing Busy slot through settlement. The oneshot receiver's abandonment drops the in-flight native count future, preserving the driver's Lease retirement behavior. Native observed_txn and closed_reason_settled govern return_session. Native transaction-end refreshes use the captured console refresh state, and a retired lease's actual release is awaited before scheduling owed refreshes. Close/disconnect orphan the count through the existing drop_session ownership checks. A stale count cannot return its session into a replacement slot. Finished RunState, rows, result references, and history are preserved.

Frontend Last captures the tab target, table/query/page object, text, and page size. Its context guard follows the count through console setup, queued page dispatch, and acceptance. A changed context or closed tab drops the reply without changing current text, results, or page. Tests call actual lastTablePage with deferred IPC replies.

README and architecture load-bearing decisions, command signature, reconciliation, and paging notes describe the PostgreSQL metadata versus SQL Server tab-session distinction.

Rationale

The root accepted this design before implementation. Refusing raw WHERE counts would address DATEFIRST alone and miss other session settings and uncommitted native rows. A new LastPage execution request would unnecessarily broaden pagination and result contracts. Reusing the moved-exclusive-session shape enforces the ownership already used by runs and transaction commands. The small count task uses that same slot and is not an independent execution lane.
